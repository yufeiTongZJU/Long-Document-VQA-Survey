Names link to the recorded paper URL or a Google Scholar title search; hover to see the paper title. The year beside the name is the bibliography year; the smaller **(YY.MM)** alongside it is the first-release date. Scroll horizontally to view all 13 columns.

**Columns:** Parsing = OCR / Deep; evidence organization and retrieval = Modality / Gran. / Mechanism / Acq.; generation and learning = Agent / Reasoning / Model / Learning. **Deep** = Deep Parsing; **Gran.** = Granularity; **Acq.** = Acquisition; **Eval.** = Evaluation.

**Key distinction:** Iterative acquisition adds evidence beyond the current set through feedback. Multi-step reasoning can instead revisit existing evidence, so One-shot acquisition and Multi-step reasoning may coexist.

## How to read the table

### Dates, venues, and symbols

- **Dates and order.** YY.MM is the first-release month, preferably the first arXiv version; an earlier official release, or the official release when no preprint exists, takes precedence. Within task groups, methods follow final conference submission deadlines, then first release within each conference; preprints and journal papers are inserted by first release. Bibliography, venue, and first-release years can differ.
- **Venue superscripts.** F = Findings; W = Workshop; D = Datasets and Benchmarks; S = Short; I = Industry; C = competition reports.
- **Symbols.** <img src="../assets/check.svg" width="12" alt="Yes"> = present; <img src="../assets/cross.svg" width="12" alt="No"> = absent. **--** denotes unreported, unconfirmed, or inapplicable information. **+** combines components; **/** separates alternatives.

### Classification

- **OCR** records dependence on external extraction or textualization, including OCR, PDF text extraction, and VLM transcription or description. Methods combining extracted text with page images also count as OCR-dependent.
- **Deep** lists structure types directly: Summary captures page/document semantics; Tree captures section hierarchies and containment; Graph captures content relations. Element transcription alone and runtime reasoning memory do not count as Deep Parsing.
- **Modality** describes evidence-side matching representations: Uni(T) = text, Uni(V) = vision, Mixed(T/V) = both.
- **Granularity** describes the evidence supplied to generators, or returned by retrieval-only methods: Document, Page, and Elem. (Element). Elements include independently accessible text blocks, sections, charts, tables, and region crops.
- **Acquisition:** Iterative uses generation or control feedback to acquire evidence beyond the current set. One-shot permits fixed multistage retrieval, graph traversal, reranking, and refinement without feedback-driven expansion.
- **Agent** distinguishes Single and Multi by runtime reasoning roles and collaboration. **Reasoning:** Single-pass includes a single chain of thought, structured decoding, or a fixed multi-agent pipeline; Multi-step revises judgments/actions through repeated feedback.
- **Model** gives the main generator model family. **Learning** records added generator-side training, including answering, control, or tool components; it does not mean every module is trained. Structure and training types are listed directly; a standalone <img src="../assets/check.svg" width="12" alt="Yes"> in Learning indicates added training without a listed type. SFT = supervised fine-tuning; RL = reinforcement learning. Generation attributes are inapplicable to retrieval-only methods.

### Mechanism and evidence mappings

- **D / P / E** = document / page / element; superscripts **T / V / TV** = text / visual / both.
- In **→**, the left side is evidence returned by retrieval or selection; the right side is the generation input. Without an arrow, retrieval and generation use the same granularity and modality. Retrieval-only methods are labeled by their returned unit.
- Superscript **t** marks added retrieval, scoring, or page-selection training.
- Parentheses after model names specify evidence forms. **Semicolons** separate independent paths; an arrow applies only within its path. **[ ]** groups multiple evidence items; commas denote parallel items.

### Evaluation

Only dimensions quantitatively reported in the original paper are listed: **Ans.** = answer quality; **Ret.** = evidence retrieval, usually page-level hits, recall, or ranking; **Loc.** = within-page element/region localization or coverage, such as IoU or region-overlap recall; **Eff.** = processing efficiency and cost; **Rob.** = robustness to controlled perturbations.

**Exceptions (a):**

- Ret. is document retrieval for DocMMIR, DocPC, NeuSym-RAG, and Agentic Hybrid (EXTRACTOR); document identification for HiKEY; and additionally document recall for HEAVEN.
- LILaC evaluates layout-element retrieval; Doc-Researcher evaluates document/page/layout-element retrieval.
- G<sup>2</sup>-Reader Ret. measures semantic coverage of evidence statements; LFRAG includes element-ID matching; HierDoc includes region-ID-set F1; MoDora evaluates evidence-node recall and filtering.
- ReAlign Loc. measures overlap between attention regions and supervised boxes; RGenCite includes VLM-assessed evidence support; Lang2Act measures the proportion of internal attention falling within gold regions.
- MMRetHeads evaluates pages and layout regions on MMDocIR; LMS-Retrieval Ret./Loc. measure layout-element recall and region coverage.
