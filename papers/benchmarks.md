## Notation and notes

**Groups and dates.** Benchmarks are grouped by primary evaluation target and input scale. Within task groups, ordering follows final conference submission deadlines, then first release within each conference; preprints and journal papers are inserted by first release. **(YY.MM)** denotes the first-release month, preferentially the first arXiv version; an earlier official release, or the official release when no preprint exists, takes precedence.

**Venue superscripts.** F = Findings; W = Workshop; D = Datasets and Benchmarks; S = Short; I = Industry; C = competition reports.

**Scale and input.** Open and Closed denote a cross-document candidate collection and a given single document, respectively; Open/Closed supports both. **#Docs** counts documents or independent page inputs. **#Pages** is the average number of input pages per question, using a document-level mean when per-question statistics are unavailable; Open counts the full candidate collection for that question, and an independent image counts as one page. **#Tokens** is the mean text-token count per input document. **#QA** counts questions, queries, or localization tasks.

**Question types and evidence.** MD, MP, and SP denote multi-document, multi-page, and single-page evidence requirements, respectively; Unans. denotes questions unanswerable from the given evidence. <img src="../assets/check.svg" width="12" alt="Yes"> / <img src="../assets/cross.svg" width="12" alt="No"> indicates inclusion/exclusion; parentheses give proportions. In **Source**, TXT/L/C/TAB/I denotes text/layout/charts/tables/images. **Gran.** denotes the verification granularity supported by public evidence annotations: Doc. = Document; Elem. = Element. In open-domain settings, page annotations with document identities also support document verification, which is not listed again.

**Evaluation (Eval.).** Capabilities supported by the benchmark and its public annotations:

- **Ans.**: answer quality.
- **Ret.**: evidence retrieval, typically page/whole-image hits, recall, or ranking.
- **Loc.**: within-page element or region localization, such as IoU-based evaluation.
- **Eff.**: processing efficiency and cost.
- **Rob.**: robustness to controlled perturbations.

**Exceptions (<sup>a</sup>).** ViDoRe supports Ans. only on subsets with public answers. For Ret.:

- SPIQA retrieves figures/tables.
- DocMMIR, DocViRe, PaperScope, AIRQA-REAL, and AirQA retrieve documents.
- M3DocVQA measures recall by the documents containing retrieved pages.
- M4DocBench covers documents, pages, and layout elements.
- SynthDocBench matches chart/element IDs.
- UDA measures text-evidence coverage.
- MMDocRAG includes text/image-segment selection.
- LFDocQA includes element-ID matching.
- PaperPDF matches paragraph/figure/table IDs.

Loc. for GroundingDocQA-Bench and DoCoG-Bench includes segmentation masks.

**Pre-extracted inputs (&#42;).** ArXivQA uses pre-extracted scientific figures; SPIQA uses pre-extracted figure/table images and text; MMDocRAG generation evaluation uses pre-extracted text/image segments; PaperScope supplies pre-parsed paper text and images. These settings do not directly evaluate the complete parsing process from raw pages.
